# What separates the part of shed-os/shedos-release that came out of the monolith from
# the monolith it came out of. Nothing here is a free pass: each path was opened and read
# before it was written down, and an entry that stops matching fails the run.
#
# This is a tree-form enumeration: every path is written the way this repository holds it
# and every `content` line is pinned <monolith blob>..<carved blob>. What it governs is
# the source. This repository builds one package, shedos-meta, and that package is
# generated rather than carved — the comparison for it is the diff against the monolith's
# own generated metapackage, kept at the end of this file.

# --- (a) where the content came from ----------------------------------------------
#
# Carve map: tools/carve-maps/shedos-release.paths. It takes packages/ whole, leaves the
# npm cache behind, and moves the two metapackage generators from scripts/ to tools/:
#
#   path packages/
#   except packages/npm-cache
#   rename scripts/resolve-meta-closure.sh:tools/resolve-meta-closure.sh
#   rename scripts/render-meta-depends.sh:tools/render-meta-depends.sh
#
# 105 commits and 58 paths, carved from the monolith at 8ce1763e and merged into this
# repository's own history rather than starting one — this repository existed first. The
# npm cache is three tarballs a Neovim plugin build once needed; the monolith's tree no
# longer has them and no input here ever did.
#
# The relationship between the two copies until the cutover: the monolith is still the
# fleet's producer and its packages/ is still its own build input. A list change lands
# there first and propagates here. After the cutover these are the originals and the
# monolith's are gone with it.

# --- (b) the 4 transformed files --------------------------------------------------
#
# The two generators are rewritten rather than edited, and the two files they read are
# their output or their input. Everything else came across byte-identical.
#
# resolve-meta-closure.sh keeps its method — an isolated pacman database in a tempdir and
# a broad-root -Sp — and changes what it reads, what it writes, and what it claims. It
# used to run awk over the renderer's source to find the shedos_conflicts array the
# renderer would emit; both read packages/meta-conflicts.txt now. It writes a marker
# beside any closure name the release manifest also names, which today is cage and
# nothing else. And the virtual-provider check became a report: the monolith's version
# asks pacman to resolve each virtual and reads the install chain that comes back as the
# provider set, so it passed with jack2 removed from the conflicts file; this one inverts
# what every package declares it provides, which is the real enumeration, and against that
# the conflicts list is not complete. Which alternatives a metapackage should forbid is a
# decision with product consequences, so the run says what it sees and test/meta pins the
# list by name.
#
# render-meta-depends.sh takes the release from release-manifest.toml's [release].version
# rather than from a VERSION file, takes the ShedOS packages from the manifest's entries
# rather than from a nine-name array written inside it, pins each of them to the exact
# release the channel serves, and refuses a closure and a manifest that disagree about a
# replaced name in either direction. It also keeps the metapackage out of its own depends:
# the manifest names every package the channel serves and that now includes shedos-meta.
# Its sorts are pinned to the C collation, because the order they produce is the order the
# generated PKGBUILD ships and en_US puts atk before at-spi2-core where C does the
# opposite — a desk and a runner would otherwise render two different files. It reads each list it excludes on into a variable
# first, because a list read through a process substitution takes its failure with it and
# a missing aur-norepublish.txt would come back as no names at all. Its heredocs name the
# org.
#
# .meta-closure.txt is the same 1268 Arch packages the monolith's copy holds — regenerated
# against core/extra/multilib and compared name for name, no drift — carrying the new
# header and the one marker.
#
# installer-only.txt gains calamares, which is the one place these two copies disagree on
# content. The monolith's renderer learns which ShedOS packages to install from a list
# written inside itself and calamares was never on it, so nothing there ever had to say
# calamares is installer-only. This one reads the manifest, which names every package the
# channel serves, so without the line the installer would be a dependency of shedos-meta
# and would land on every machine that installs it. The monolith's copy gains the line
# when the monolith is next open for edits.
