# What separates shed-os/calamares from the monolith it came out of. Nothing here is a
# free pass: each path was opened and read before it was written down, and an entry that
# stops matching fails the run.
#
# This is a tree-form enumeration: every path is written the way the carved repository
# holds it and every `content` line is pinned <monolith blob>..<carved blob>. What it
# governs is the source. The two builds' bytes are a separate question, asked on demand
# with tools/build-reference.sh; the answer this repository got is kept at the end of this
# file rather than carried as an allowlist that goes stale on the next rebuild.

#
# Source package: calamares. This repository is not only the package — it is the ShedOS
# fork of the installer itself, whose own history holds the root, so the carve map takes
# the packaging directory one level down:
#
#   path packaging/calamares/
#   rename packaging/calamares:packaging
#
# One file arrives that way, packaging/PKGBUILD, and the pipeline is pointed at
# `packages: ["packaging"]`. The carve took packaging/calamares as the monolith held it at
# 83d5c3d0, and the comparison below is against 8ce1763e, which is where the monolith
# stands now.

# --- the artifact comparison, kept as history ---------------------------------------
#
# Run once, before this file took its tree form. Reference: built from packaging/calamares
# at monolith commit 93d7442b, which was origin/main at the time, under a scratch
# MAKEPKG_CONF carrying the same BUILDENV and OPTIONS the pipeline writes beside its own
# config. Its pkgver-pkgrel came from that PKGBUILD unmodified and matched the published
# 3.4.2-4, so nothing was patched to make the two agree. Candidate: the artifact the
# staging database recorded.
#
# Nothing differed. All 587 paths were byte-identical, build IDs included.
#
# Reproducing that takes three properties of the build environment, and a reference that
# skips any of them reports differences that belong to the builder rather than to the
# package:
#
#   LC_ALL=C             the locale the pipeline's container runs in
#   SOURCE_DATE_EPOCH    set to the candidate's .BUILDINFO builddate — makepkg takes it
#                        from the environment, and Qt's resource compiler stamps it into
#                        .rodata as a millisecond timestamp
#   the build directory  /__w/calamares/calamares/packaging, where the runner checks the
#                        repository out — a workstation cannot create that path without
#                        root, so bind it there instead: bwrap --tmpfs / with /usr /etc
#                        /var /home /tmp /run /dev dev-bound, the usual /bin /lib /sbin
#                        symlinks, and --bind <reference tree> /__w
#
# The directory is the surprising one. Two things here follow its text and its length:
# src/libcalamaresui/viewpages/QmlViewStep.cpp reaches a Qt logging macro that bakes
# __FILE__ into libcalamaresui, and CMake blanks the build-tree RPATH at install time
# without shrinking .dynstr, which leaves every binary carrying one spare NUL for every
# character of the build path. Neither changes what the package does, and both would
# report as a content difference on every ELF file in it if the reference were built
# anywhere else.
#
# A byte difference found by a later comparison is a real difference, not a build that
# drifted: this package's two builds have been equal once already, on the terms above.
