# What separates shedman from the monolith it came out of. Nothing here is a free
# pass: each path was opened and read before it was written down.
#
# This one does not take the shape of the others. shedman is a NEW package name — the
# monolith has never built one, so there is no reference package to compare against and
# tools/build-reference.sh has no packaging directory to build. The comparison is against
# the monolith FILES the carve took, and the entries below are the whole of what moved.

# --- (c) everything else is byte-identical ----------------------------------------
#
# Every carved file not named in (b) is byte-for-byte the monolith's. Measured by
# comparing `git hash-object` for each carved path against the monolith blob at
# 03404a92: 27 identical, 15 transformed, 0 different, 0 missing over the 42 package
# files, and 491 identical over the carved test files. The carve itself is the same
# claim before any transform: 42 of 42 blobs identical, 158 commits matching the
# monolith's log for those paths line for line, plus the two merge commits filter-repo
# keeps and `git log -- <paths>` prunes.
#
# One limit is worth writing down. Fourteen of the verbs were once /usr/bin/shedos-*
# tools, and those paths are still live back-compat shims shedos-system ships. A carve
# map cannot chase history through a path the monolith still uses for something else —
# the rename would carry the shim's later commits onto the verb — so those fourteen
# files' history in this repository starts at the commit that made them verbs. The bash
# completer's move out of /etc/bash_completion.d is replayed, because that path is gone.
