# What separates shed-os/cage from the monolith it came out of. Nothing here is a free
# pass: each path was opened and read before it was written down, and an entry that stops
# matching fails the run.
#
# This is a tree-form enumeration: every path is written the way the carved repository
# holds it and every `content` line is pinned <monolith blob>..<carved blob>. What it
# governs is the source. The two builds' bytes are a separate question, asked on demand
# with tools/build-reference.sh; the answer this repository got is kept at the end of this
# file rather than carried as an allowlist that goes stale on the next rebuild.

# --- the artifact comparison, kept as history ---------------------------------------
#
# Run once, before this file took its tree form. Reference: built from packaging/cage at
# monolith commit 03404a92, then origin/main, with pkgrel raised from 2 to the published
# 4 — the carve republished without a monolith release behind it, and pkgrel is a
# .PKGINFO field. Candidate: the artifact the staging database recorded. The two
# .BUILDINFO package lists came out equal in both directions.
#
# The reference was the same bytes the monolith's own build published: the cage the
# channels served as 0.3.0-2 carried that exact usr/bin/cage. So what follows was a
# difference between the two repositories and not between two ways of building.
#
# One path differed and it was the binary, and what differed inside it was the version
# string. cage builds that string out of git: meson.build asks git for the short commit
# and the branch of whatever repository the build tree sits in and falls back to the
# plain project version when there is none. The pipeline builds inside its checkout of
# shed-os/cage, so the answer is that repository's HEAD —
#
#     Cage version 0.3.0-579273d (branch 'main')
#
# where 579273d is a commit of the carved repository. The reference is laid out with git
# archive, which the recipe requires, so no repository sits above it and the string stays
#
#     Cage version 0.3.0
#
# which is also what the monolith's published build says. That was the whole difference,
# read rather than assumed:
#
#   CAGE_VERSION is interpolated in two places and .rodata is 48 bytes longer,
#   exactly twice the 24 characters the suffix adds
#
#   every section after it is the same size and sits 48 bytes further on, and
#   .data, .data.rel.ro, .init and .fini are byte-identical
#
#   .text is the same size and, with addresses masked, the same 4913
#   instructions in the same order — the same code reaching constants that moved
#
# The pair it was pinned to:
#
#   usr/bin/cage
#     02524fe3df513766cacae676d74f3ecf208a2e4f914121ebe198b3a8b672c9d1
#     3f4ce2bd919463fb1251c5004f99f16d5a252fa0cb2655b996981a79c55b0f2e
#
# The candidate half of that pin moves whenever shed-os/cage's HEAD does, which is why it
# is history here rather than an expectation: anyone comparing the artifacts again builds
# the reference with tools/build-reference.sh and reads the difference against the
# account above.
