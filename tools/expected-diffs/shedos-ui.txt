# What separates shed-os/shedos-ui from the monolith it came out of. Nothing here is a
# free pass: each path was opened and read before it was written down, and an entry that
# stops matching fails the run.
#
# One file for one repository, where there used to be five for five packages. The
# workspace is one tree with one history and its members share a dependency graph; a walk
# of it answers for all of them at once, and the five package-form files could not see a
# source file at all — six .gitignores, six Cargo.locks and a Cargo.toml left this tree
# for the workspace root and no enumeration of installed bytes could say so. Section (e)
# does.
#
# This is a tree-form enumeration: every path is written the way the carved repository
# holds it and every `content` line is pinned <monolith blob>..<carved blob>. What it
# governs is the source. The five packages' bytes are a separate question, asked on
# demand with tools/build-reference.sh; the answers this repository got are kept at the
# end of this file rather than carried as allowlists that go stale on the next rebuild —
# and they did go stale, which is why they are history. A republish nobody asked for,
# on an Arch toolchain that had moved underneath an unchanged tag, invalidated all five
# candidate halves at once.

# --- (a) where the content came from ----------------------------------------------
#
# Source packages: shedos-greeter, shedos-power, shedos-switcher, shedos-tour and
# shedos-screensaver, plus shedos-prompt-ui, which is the library the other five link
# against and builds no package of its own. Carve map: tools/carve-maps/shedos-ui.paths,
# a `path` and a `rename` per packaging directory — six pairs — so every package keeps a
# directory of its own, the crate paths between them still resolve, and each PKGBUILD
# stays beside the crate it builds.
#
# The map selects 198 monolith files. 184 of them are here, and the fourteen section (e)
# accounts for went to the workspace root when the crates were assembled into one tree, or
# were renamed in place.
# The carve took the six directories as the monolith held them at 9141eca7, and the
# comparison below is against 8ce1763e, which is where the monolith stands now.

# --- (b2) the 10 files with no monolith counterpart --------------------------------
#
# The workspace itself: Cargo.toml, which declares the thirteen members, the shared
# dependency versions, the release profile the members gave up and the [workspace.package]
# metadata naming this repository, and Cargo.lock, the one lock the whole tree resolves
# against.
#
# Two suites the pipeline runs from the checkout: test/cargo/run.sh, which runs every
# crate's unit tests at once against the committed lock — `cargo test --locked
# --workspace`, so the lock is held to the manifests as well — and test/screensaver/run.sh,
# which drives the built shedos-screensaver binary through its read-only modes. Neither
# existed in the monolith, where each crate was built on its own.
#
# The verb contract, which the monolith never held these two packages to. The dispatcher
# runs anything under /usr/libexec/shedman and both shipped a verb with nothing describing
# it, so `shedman help` listed two names with no line beside them:

#   shedos-screensaver/tree/usr/share/shedman/verbs.d/screensaver.toml
#   shedos-tour/tree/usr/share/shedman/verbs.d/tour.toml — with completes = false, because

#   shedos-tour/man/shedman-tour.1.scd — the page the declaration points at, which is

# --- the artifact comparisons, kept as history ---------------------------------------
#
# Five comparisons, one per package, run before this file took its tree form. Each
# reference was built from the monolith's own packaging directory under a scratch
# MAKEPKG_CONF carrying the BUILDENV and OPTIONS the pipeline writes beside its own
# config, with pkgrel raised to the published one — the carve republished without a
# monolith release behind it, and pkgrel is a .PKGINFO field. Each candidate was the
# artifact the staging database recorded, and both .BUILDINFO package lists came out
# equal in both directions every time.
#
# In all five, one path differed and it was the binary. The monolith builds each crate on
# its own and the workspace builds its members from the root, so a source path the
# monolith's build records as
#
#     src/render.rs
#
# the candidate records as
#
#     shedos-tour/src/render.rs
#
# and the crate the packages share is an absolute path on one side against a
# workspace-relative one on the other. Read rather than assumed, per package: the source
# paths in each binary, how many of them differ, and what that does to the sections —
# .rodata carries the strings and grows, .relro_padding shrinks by as much because the
# linker pads the segment back to the size it was, and .text is the same instructions
# once addresses are masked, give or take one sixteen-byte run of int3 padding.
#
#   shedos-greeter       307 source paths, 13 differ; .rodata +512, .relro_padding -512;
#                        620,051 instructions both sides
#   shedos-tour          271 source paths, 7 differ; .rodata +256, .relro_padding -256;
#                        547,612 instructions both sides
#   shedos-power         221 source paths, 4 differ; .rodata +64, .relro_padding -48;
#                        437,000 against 437,016 instructions, the padding the only
#                        thing the two lists do not share
#   shedos-switcher      287 source paths, 7 differ; .rodata +128, .relro_padding -112;
#                        560,780 against 560,796 instructions, likewise
#   shedos-screensaver   338 source paths, 28 differ; .rodata +264, .relro_padding -272;
#                        868,162 against 868,146 instructions, likewise
#
# Making the strings match does not close it. A reference built with
# --remap-path-prefix — through a rustc shim, so the flag stays out of what cargo hashes
# into a package's metadata — comes out with every section exactly the candidate's size

# moving too. What that measures is that the names rustc records and the order the
# constants land in are coupled; which mechanism couples them was not isolated. No
# reference-side flag makes these two builds the same bytes.
